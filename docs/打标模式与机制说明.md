# TagMatrix 打标模式与执行策略机制说明

本文档详细说明了 TagMatrix 系统中打标任务的核心机制，包括“执行策略”与“打标模式”的区别，以及相关的核心代码实现位置。主要供后续系统迭代和扩展（如引入主标签优先算法）参考。

## 1. 核心概念区分

系统现已将对历史数据的处理逻辑与新标签生成逻辑拆分为两个独立的概念：

### 1.1 执行策略 (Execution Strategy)
控制当一条数据重新执行打标任务时，如何处理它**原有的自动标签**。
- **追加模式 (append)**：保留该数据原有的标签，直接追加写入本次命中的新标签。
- **覆盖模式 (overwrite)**：在写入新标签前，先**批量清除**该数据原有的、由打标引擎自动打上的标签（`source = 'auto_rule'`）。

### 1.2 打标模式 (Tagging Mode)
控制当一条数据在本次打标任务中**同时命中多条规则**时，如何生成并分配最终的标签。
- **多标签模式 (multiple)**：默认行为。所有命中的规则都会生成对应的标签，且地位同等（`is_primary = false`）。
- **单标签模式 (single)**：即使命中多条规则，也仅取优先级最高的**一个**标签入库。
- **混合模式 (mixed)**：所有命中的规则都会生成标签，但**优先级最高**的那一个标签会被设为主标签（`is_primary = true`），其余同等为次标签。

## 2. 当前打标排序机制 (MDCT 算法)

在“单标签模式”与“混合模式”下，当一条数据同时命中多个规则时，系统现已全面升级并采用 **多维共识打标算法 (Multi-Dimensional Consensus Tagging, MDCT)** 来决定主标签归属。

MDCT 算法通过对以下四个维度的动态加权打分，彻底告别了过去单一依赖 ID 兜底的机械逻辑：

1. **人为静态权重 (PriorityScore)**：基于用户配置的优先级，占有决定性的基础权重。
2. **规则逻辑深度 (ComplexityScore)**：解析底层 AST 树的复杂度（如逻辑层级深度、精确匹配算子比例）进行打分。
3. **数据置信度 (CompletenessScore)**：考察数据本身的完整性，非空字段越多，对标签的确信度越高。
4. **AI 语义裁判 (AIConsensusScore)**：当基础得分相近，触发“神仙打架”平局时，系统将通过大语言模型介入裁决，并记录判定理由（需配置开启该维度）。

系统会根据这四个维度的加权总和，对所有命中的规则进行归一化排序。总分最高的规则将胜出，成为该数据的主标签（或唯一标签）。

## 3. 核心代码位置与执行逻辑

相关的 MDCT 处理与调度逻辑集中在后端引擎中：

**核心文件路径**:
- 任务引擎调度：`internal/service/taskengine/taskengine_service.go`
- 算法评估引擎：`internal/service/taskengine/mdct_scorer.go`

### 3.1 MDCT 算法调用逻辑
系统会将当前数据命中的所有规则收集到 `matchedRules` 数组中，随后调用 MDCT 引擎进行打分排序：

```go
// 代码位置: processRecords 方法内部

// 接入 MDCT 多维共识打标算法引擎进行打分、仲裁与排序
scoredRules := scorer.EvaluateAndSort(ctx, dataMap, matchedRules, tagMode)
```

### 3.2 模式应用逻辑
在 MDCT 算法计算完毕后，引擎会直接对按得分降序排序的 `scoredRules` 数组进行模式分发：

```go
// 根据打标模式 (tagMode) 处理命中的规则
if tagMode == "single" && len(scoredRules) > 0 {
    // 单标签模式：只取 MDCT 综合打分最高的第一个
    scoredRules = scoredRules[:1]
}

for i, sr := range scoredRules {
    isPrimary := false
    // 混合模式：综合得分最高的第一个作为主标签
    if tagMode == "mixed" && i == 0 {
        isPrimary = true
    }
    // ... 将带有归一化置信度与 AI 仲裁理由的数据入库
}
```
