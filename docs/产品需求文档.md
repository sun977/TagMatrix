# TagMatrix 产品需求与演进文档 (PRD)

> **文档说明**：本文档沉淀了 TagMatrix 从初期构想到 V3.0 及未来演进的核心需求脉络，作为项目的功能基线与架构参考。

---

## 1. 项目概述 (Project Overview)

**TagMatrix** 是一款专业的可视化数据打标与处理系统。通过灵活的规则引擎和 AI 智能辅助，用户可以自定义业务标签与匹配规则，系统将自动对导入的无序数据进行筛选、匹配与打标，最终输出带有业务标签的结构化资产。

---

## 2. 核心功能矩阵 (Core Features)

### 2.1 灵活的数据与资产流转
*   **多数据源接入**：支持 Excel、CSV、数据库 (SQLite/MySQL/PostgreSQL等) 的无缝导入。
*   **资产隔离与互通**：除原始数据外，系统的**标签结构**、**匹配规则**均支持独立导入导出（CSV/JSON 格式），便于业务资产的沉淀与跨环境迁移。
*   **系统保留字段隔离**：系统内部生成的字段统一使用 `TagM_` 前缀，严格防止与用户的原始数据字段产生冲突。

### 2.2 自定义标签与无极规则引擎
*   **全局标签体系**：支持自定义标签名称、属性说明，构建树状业务标签库。
*   **精细化规则定义**：
    *   **多字段联合匹配**：允许同时指定一个或多个源数据字段进行内容匹配。
    *   **试运行机制 (Dry Run)**：在配置匹配算子时，提供实时预览功能。用户可反复调整参数直至结果满意，从根源上杜绝算子配置错误导致的“全量打标灾难”。

### 2.3 自动化执行与任务级风控
*   **自动化流水线**：一键触发 -> 自动数据匹配 -> 自动执行打标 -> 自动记录审计日志。
*   **任务批次管理与回退 (Rollback)**：每轮打标任务均生成独立任务编号与快照。若对打标结果不满意，支持一键回退到该批次执行前的任意数据状态。
*   **白盒审计日志**：系统详细记录每条数据的打标过程（触发了哪条规则、匹配依据、计算方式、最终结果），实现打标逻辑 100% 可解释、可追溯。

### 2.4 全局智能副驾 (AI Copilot)
*   **大语言模型接入**：预留标准 AI 接口（兼容 OpenAI 协议）。
*   **对话即交互**：用户可通过自然语言与系统对话，让 AI 辅助查阅数据、筛选表单、分析数据并直接生成 SQL 语句。
*   **使用向导**：AI 同时作为系统的智能说明书，随时解答用户关于软件操作的疑问。

## 3. 打标模式与机制 (Tagging Mechanisms)

系统支持三种极具弹性的打标模式，以适应不同复杂度的业务场景：
1.  **单标签模式**：强互斥场景。一条数据只能被赋予一个标签（如：性别）。
2.  **多标签模式**：宽泛归类场景。一条数据可同时打上多个平行标签（如：高消费、活跃、数码控）。
3.  **混合模式 (主副标签)**：层级归类场景。一条数据可指定一个“主标签”，以及若干个“次级辅助标签”。

---

## 4. 数据看板与可视化 (Dashboards)

**【打标数据看板】**是用户验收成果的核心视窗，具备以下特性：
*   **任务级视图**：可自由切换并查看“指定打标任务批次”结束后的数据结果。
*   **动态列渲染**：根据原始数据自动解析表头，用户可自定义展示哪些字段、隐藏哪些字段。
*   **全局与定向过滤**：支持对所有展示字段或特定字段进行精准的数据检索与筛选。
*   **行级溯源**：在看板中直接查看任意一行数据的“打标过程审查记录”，判断逻辑合理性。

## 5. 架构演进与未来规划 (Roadmap)

### 5.1 V3.0 架构大重构 (已完成)
*   **引入「数据集 (Dataset)」概念**：异构数据源不再混淆，实现物理与逻辑上的强隔离。
*   **解耦「标签」与「规则」**：标签作为全局资产存在，而规则与特定的“数据集”强绑定，彻底解决不同表头带来的规则张冠李戴问题。

### 5.2 未来需求规划
*   **跨表打标签 (Cross-Table Tagging)**：允许高阶用户通过编写 SQL 创建聚合视图 (View)。视图可融合多个数据集的字段，打标引擎可直接基于视图层进行联合判定。
*   **操作审计与误删恢复**：建立全局系统操作日志，记录用户或管理员调用的后端接口、删除动作等，并支持底层数据记录的防误删恢复 (Soft Delete Recovery)。
*   **硬核开发者后门**：提供专属的数据库操作页面，允许管理员直接对底层 SQLite 物理表执行查询与数据干预。

## 6. 系统概念澄清 (Glossary)

为了消除开发与维护中的歧义，特对系统中的“三个模式”作严格定义：

1.  **开发模式 (Development Mode / Dev Build)**
    *   **维度**：运行环境概念。
    *   **触发**：通过终端输入 `wails dev` 启动。
    *   **行为**：前端开启热重载 (Hot Reload)；数据库 (`data.db`) 和日志 (`app.log`) 直接写在项目根目录 `./`，方便开发者随时追踪修改。
2.  **调试模式 (Debug Mode)**
    *   **维度**：应用功能概念（用户侧开关）。
    *   **触发**：在【全局设置】UI 中切换。
    *   **行为**：不论是开发环境还是已打包的生产环境 (`.exe`)，开启后 Logger 级别提升至 `Debug`，底层 GORM 将打印每一条 SQL 语句及耗时（默认只记录 >200ms 的慢查询），用于排查线上疑难杂症。
3.  **开发者模式 (Developer Mode)**
    *   **维度**：高级权限概念（隐藏入口）。
    *   **触发**：在【全局设置】的特定区域“连击 5 次”解锁。
    *   **行为**：左侧导航栏暴露高危菜单【系统数据库管理】，允许硬核玩家/实施人员直接通过 SQL 或表格穿透操作底层物理数据。
