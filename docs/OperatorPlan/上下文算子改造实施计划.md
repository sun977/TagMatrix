# TagMatrix 算子上下文升级与计数器算子实施开发计划

## 一、 开发目标
在 TagMatrix (V4.0) 的无状态匹配器引擎 (`matcher`) 中引入 `context.Context`，以支持有副作用的执行状态记录（如行级计数、全局计数），并实现新的计频算子与非短路并发节点。

---

## 二、 实施步骤拆解

本次重构与开发分为 4 个主要阶段，遵循“从底层数据结构 -> 核心引擎 -> 上层业务调用”的顺序。

### Phase 1: 基础设施构建 (Context 容器定义)
**目标**：构建用于透传状态的数据结构和帮助函数。
**涉及文件**：`internal/pkg/matcher/context.go` (新建)

1. **定义 Context Keys**：
   * 定义 `type ctxKey string`，避免上下文键名冲突。
   * 声明两个常量：`globalCounterKey` 和 `rowCounterKey`。
   * 声明 `currentTagKey`，用于记录当前正在匹配的标签名。

2. **定义计数器结构体**：
   * 定义 `GlobalCounter` (底层封装 `sync.Map`，提供 `Inc(tagName string, delta int)` 和 `GetAll() map[string]int` 方法)。
   * 定义 `RowCounter` (单行生命周期，无需并发控制，可直接使用 `map[string]int`)，提供相同的接口方法。

3. **实现注入与提取函数**：
   * `WithGlobalCounter(ctx context.Context, gc *GlobalCounter) context.Context`
   * `GetGlobalCounter(ctx context.Context) *GlobalCounter`
   * （同理实现 `RowCounter` 和 `CurrentTag` 的 With/Get 方法）

---

### Phase 2: 模型扩展与 DTO 修改
**目标**：使对外的数据模型支持携带多频次统计结果。
**涉及文件**：`internal/model/dto.go`

1. **修改 `TaggedRecordDto`**：
   * 在结构体中追加字段：
     ```go
     TagHits map[string]int `json:"tagHits,omitempty"` // 记录该行数据中各标签的命中频次
     ```

2. *(可选)* **修改 `DashboardStats`**：
   * 为后续全局统计展示做预留：可以扩展 `GlobalTagHits map[string]int` 字段。

---

### Phase 3: 核心引擎改造 (Matcher 升级)
**目标**：打通 `Context` 透传链路，支持新的 AST 节点与带有计数的副总用算子。
**涉及文件**：`internal/pkg/matcher/matcher.go`

1. **AST 节点扩展**：
   * 在 `MatchRule` 结构体中新增字段：
     ```go
     EvaluateAll []MatchRule `json:"evaluate_all,omitempty"`
     ```

2. **核心函数签名修改与透传**：
   * 修改 `func Match(data interface{}, rule MatchRule) (bool, error)` -> `func Match(ctx context.Context, data interface{}, rule MatchRule) (bool, error)`
   * 全局搜索该文件内的 `Match` 递归调用，并在调用处补齐 `ctx` 参数。
   * 修改 `evaluateCondition` 函数，同样增加 `ctx` 作为第一个参数。

3. **增加 `EvaluateAll` 解析逻辑**：
   * 在 `Match` 函数的开始部分，处理 `rule.EvaluateAll` 的情况。
   * 逻辑：遍历子规则调用 `Match`，但不短路退出。只要有任意一个子规则返回 true，本节点最终就返回 true；否则 false。（核心区别于 `Or` 的短路退出）。

4. **新增计数算子实现**：
   * 在 `evaluateCondition` 的 `switch operator` 中，增加 4 个 case：
     * `count_contains`：利用 `strings.Count(actualStr, expectedStr)` 计算次数 $N$。
     * `count_regex`：利用正则对象的 `FindAllStringIndex` 计算匹配次数 $N$。
     * `row_inc`：$N = expected$ (将其转为 int)。
     * `global_inc`：$N = expected$ (将其转为 int)。
   * **统一计数逻辑提取**：
     如果上述操作算出 $N > 0$：
     * 通过 `GetCurrentTag(ctx)` 获取正在匹配的标签名。
     * 获取 `GetRowCounter(ctx)` 并执行 `Inc(tagName, N)`。
     * 获取 `GetGlobalCounter(ctx)` 并执行 `Inc(tagName, N)`。
     * 最终返回 `true, nil`。

### Phase 4: 业务调用方适配 (任务引擎接入)
**目标**：在数据处理循环中，正确地初始化容器、组装上下文、提取结果并处理编译错误。
**涉及文件**：`internal/service/taskengine/taskengine_service.go` 以及其他调用了 `matcher.Match` 的地方。

1. **修复编译错误**：
   * `taskengine_service.go` 中调用 `matcher.Match` 的地方都会报参数不匹配，准备按以下步骤重构这部分代码。

2. **注入全局状态 (Task 级)**：
   * 在类似 `RunTagTask` / `ProcessBatch` 的顶层入口，初始化：
     ```go
     gc := matcher.NewGlobalCounter()
     // （全局 Context 如果有的话，可在此注入）
     ```

3. **注入行级状态 (Row 级)**：
   * 在遍历记录的 `for` 循环内部（例如处理 `record := range recordsChannel` 的地方），每拿到一行新数据：
     ```go
     rc := matcher.NewRowCounter()
     rowCtx := matcher.WithGlobalCounter(context.Background(), gc)
     rowCtx = matcher.WithRowCounter(rowCtx, rc)
     ```

4. **注入当前标签状态 (Tag 级)**：
   * 在遍历标签进行规则匹配时（通常在 `MatchRule` 前）：
     ```go
     tagCtx := matcher.WithCurrentTag(rowCtx, tag.Name)
     ```
   * 调用：`matched, err := matcher.Match(tagCtx, parsedData, rule)`

5. **提取并保存结果**：
   * 单行数据的规则匹配全部结束后（打标完成）：
     ```go
     hits := rc.GetAll()
     taggedRecordDto.TagHits = hits
     ```

## 三、 测试与验收标准

1. **兼容性验收**：
   * 旧有的 JSON 规则（无 `evaluate_all`，无 `count_*` 算子）能在新引擎下正常工作，且速度无明显退化。
2. **并发安全验收**：
   * 使用 `global_inc` 算子，在多协程并发下处理 10 万条数据，断言最后 `GlobalCounter` 统计的总数绝对精准，不能出现数据竞争。
3. **多频次挖掘验收**：
   * 文本字段包含 3 个目标词时，`count_contains` 算子应让 `TagHits` 中该标签的值准确记录为 3。
4. **并发非短路验收**：
   * 构建 `evaluate_all` 规则，内部并列 3 个必定为 true 的 `row_inc`，单行匹配后该标签的 hit 数应准确等于 3。
