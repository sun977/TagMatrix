# V4.0 对话即打标 (Chat-to-Tag) AI 深度交互架构蓝图

> **文档状态**：架构探讨与演进规划（草案）
> **目标阶段**：V4.0
> **核心议题**：将 AI Copilot 从“被动的旁观辅助者 (Query Only)”升级为“主动的系统操作执行官 (Action Executor)”，实现基于纯自然语言的自动化建标与打标闭环。

---

## 1. 现状痛点与演进目标

在 V3.x 版本中，我们成功落地了 AI Copilot。它能够感知当前页面的上下文（例如：读取到用户正在写 SQL），并利用 LLM 辅助解答疑问或生成代码片段。

**目前的局限性（只读模式）：**
AI 只能生成文本建议，用户依然需要手动去“复制 AI 写的 JSON 规则 -> 切换到标签配置页 -> 粘贴配置 -> 切换到任务台 -> 点击执行”。这在体验上存在明显的割裂感。

**演进目标 (Chat-to-Tag)：**
让大模型直接理解用户的业务意图，将自然语言转换为系统内部可执行的 API 请求，实现**“一句话完成：创建标签 -> 绑定规则 -> 执行任务”**的全链路自动化。

---

## 2. 交互体验设想 (User Story)

**用户在 AI 侧边栏输入**：
> *"把数据集中所有 '年龄大于 60 岁，且消费低于 100 元' 的人，打上一个叫做【边缘老年用户】的标签，顺便跑一下任务。"*

**AI Copilot 的响应与动作**：
1. `[思考中...]` AI 解析出意图，认为需要调用 3 个系统指令。
2. 气泡输出：*"好的，我将为您执行以下操作：\n 1. 创建标签【边缘老年用户】\n 2. 配置对应的规则条件\n 3. 执行打标任务"*
3. 气泡底部呈现一个高亮的 **[授权并执行]** Action 按钮。
4. 用户点击后，系统自动运转，并在 3 秒后回复：*"执行完毕！已为 1,204 条数据成功打标。"*

---

## 3. 核心架构设计：Function Calling (函数调用) 机制

要让 AI 具备“手”，最标准的做法是引入 OpenAI 的 **Function Calling / Tool Calling** 机制。

### 3.1 开放后端系统 API 注册池
在 `aiengine_service.go` 中，我们需要将 TagMatrix 核心后端的 API 包装为 LLM 可识别的 JSON Schema 描述（Tools）：
*   `CreateTag(name, description)`
*   `CreateRule(dataset_id, tag_id, condition_ast_json)`
*   `ExecuteTask(dataset_id, rule_ids, mode)`

### 3.2 会话链路改造
1.  **首轮请求**：前端将用户的自然语言请求，连同上述 3 个 Tool 的 Schema 一并发送给 AI 模型。
2.  **模型决策**：大模型判断该需求需要系统介入，它不再回复纯文本，而是返回一个 `tool_calls` 结构，里面包含它编排好的函数名和参数（比如：把用户的自然语言翻译成了 AST 规则 JSON）。
3.  **拦截与授权 (Human-in-the-loop)**：
    *   出于系统安全，我们**绝不**允许 AI 直接修改数据库。
    *   后端接收到 `tool_calls` 后，将其包装成特殊的 JSON 块，通过 SSE 发送给前端 Vue。
    *   Vue 拦截到这个 JSON，在聊天气泡中渲染出漂亮的 **Action 卡片**（展示即将执行的动作和参数）。
4.  **最终执行**：用户在 UI 上点击确认，前端直接通过 Wails 绑定调用底层的 `SaveSqlTemplate` 或 `RunTaggingTask`，完成物理操作。

## 4. 关键挑战与落地路径

### 4.1 Schema 认知鸿沟
**挑战**：AI 怎么知道该用哪个字段来判断“年龄”？数据集里可能写的是 `user_age`，也可能是 `nl`。
**解法**：在触发 Chat-to-Tag 之前，必须将目标数据集的 `schema_keys`（表头字段）作为 System Prompt 强行注入给 AI。告诉它：“你只能从这些字段里挑选变量”。

### 4.2 AST (抽象语法树) 的稳定生成
**挑战**：我们的匹配引擎 `matcher.go` 依赖严谨的嵌套 JSON 结构（`{ "field": "...", "operator": ">", "value": 60 }`）。让 AI 每次都 100% 准确地吐出这个复杂结构容易发生幻觉 (Hallucination)。
**解法**：
1.  **提供 Few-Shot 示例**：在给 AI 的 Tool Description 中，提供 2-3 个标准的 AST 生成示例。
2.  **后台自校验**：后端在收到 AI 的 AST JSON 后，先走一遍我们原有的 `DryRun` 逻辑进行语法树合法性校验。如果报错，直接把报错信息扔回给 AI 让它重写，直到校验通过再展示给用户。

### 4.3 渐进式演进策略
不要一开始就做全链路。
*   **V4.1**：先实现 **Chat-to-SQL**。让 AI 侧边栏生成的 SQL 代码可以直接一键贴入数据库控制台执行。
*   **V4.2**：实现 **Chat-to-Rule**。AI 生成的规则 JSON 可以一键保存到当前所在的标签配置页中。
*   **V4.3**：最终实现跨路由的 **Chat-to-Tag 全自动工作流**。

## 5. 总结

引入 Function Calling 机制，赋予 AI Copilot 对系统的直接操作权，将彻底改变 TagMatrix 的交互范式。它将极大降低非技术人员（如运营、产品）的使用门槛，让业务人员用“大白话”就能指挥这台极其硬核的数据处理引擎。这也是 TagMatrix 迈向**下一代 Agent 级智能化工具**的必经之路。
