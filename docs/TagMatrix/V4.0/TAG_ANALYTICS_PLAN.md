# V4.0 标签体系运营与分析 (Tag Analytics & Insights) 架构蓝图

> **文档状态**：架构探讨与演进规划（草案）
> **目标阶段**：V4.0
> **核心议题**：从“能打标”向“打好标”演进。通过提供全局的标签质量评估、覆盖率分析与健康度监控，辅助业务人员对标签和规则体系进行持续的精细化运营。

---

## 1. 现状痛点与业务诉求

在 V3.x 版本中，TagMatrix 解决了“如何配置复杂规则”以及“如何快速对百万级数据执行打标”的工程问题。打标完成后，系统提供了【打标数据看板】供用户去筛选和导出结果。

**然而，在宏观运营层面上，业务人员面临着典型的“黑盒困境”：**
*   **黑盒 1 (标签冗余)**：建了几百个标签，到底哪些标签在这个数据集中从未被命中过（孤儿标签）？
*   **黑盒 2 (规则失效)**：某个标签下配置了 5 套规则，是不是其实只有 1 套规则在默默扛下了所有命中率，而其他 4 套规则因为条件过于苛刻完全失效了？
*   **黑盒 3 (大盘覆盖率偏斜)**：当前的数据集到底有多少比例的数据被成功贴上了标签？是不是全集中在某两三个“水”标签上，而真正有价值的高潜标签命中率为 0？

**核心诉求**：提供一个“上帝视角”的洞察分析台 (Insights Dashboard)，用数据反哺规则的迭代优化。

---

## 2. 核心分析指标设计

为了彻底打破黑盒，我们规划在 V4.0 中引入一个独立的 **【标签资产分析 (Tag Insights)】** 模块，核心监控以下三大类健康度指标：

### 2.1 全局标签分布与覆盖率 (Coverage & Distribution)
*   **数据集总覆盖率**：`已被至少打上 1 个标签的数据行数 / 数据集总行数`。（用于评估打标任务的整体漏斗健康度）
*   **单标签密度分布图**：通过饼图或条形图展示当前数据集中各标签的命中频次。
*   **主/副标签占比**：（针对混合模式）清晰展示哪些标签常年作为“主标签”统治数据，哪些沦为了“陪跑的次要标签”。

### 2.2 规则效能与贡献度 (Rule Effectiveness & Contribution)
*   **规则命中率排行**：在同一个标签下，清晰罗列出 `规则 A 命中了 80%`，`规则 B 命中了 20%`，`规则 C 命中了 0%`。
*   **重叠碰撞率 (Overlap Rate)**：找出“经常被同一条数据同时命中的两套规则或标签”。如果重叠率高达 95%，说明这两套规则本质上是等价的，可以建议业务人员进行合并精简。

### 2.3 孤儿资产清理预警 (Orphan Assets Alerts)
*   **无规则的空壳标签**：建了标签但在当前数据集下压根没有配置任何判断规则的。
*   **零命中率规则**：配置了规则，并且参与了打标任务，但结果是 0 命中的。
*   *这些异常指标将以“高危预警卡片”的形式直接在分析台顶端呈现，建议用户直接删除或修改。*

## 3. 架构落地建议与实现路径

此项功能的研发，在后端（尤其是数据库查询）上有一定的性能挑战。我的架构实施建议如下：

### 3.1 摒弃实时全表扫描，拥抱预计算 (Pre-Aggregation)
在数百万级的数据量下，如果每次用户打开【分析台】都去执行巨大的 `GROUP BY` 或 `COUNT(DISTINCT)` 跨表联查，SQLite 极大概率会被锁死或导致 UI 卡顿。

**解决方案**：
*   **依托现有的批处理生命周期**：在 `taskengine_service.go` 中的 `RunTaggingTask` 任务彻底执行完毕后（`status` 变更为 `completed` 时），异步触发一个分析聚合的 Hook。
*   **生成静态快照**：将分析结果固化计算后，以 JSON 格式存储到 `tag_task_batches` 表新增的 `analytics_snapshot` 字段中。
*   前端的分析台直接读取这个计算好的静态 JSON，实现毫秒级的大盘统计图表渲染。

### 3.2 基于现有的 `TagTaskLog` 深挖数据金矿
V3.x 中引入的审计日志表 `tag_task_logs` 是我们实现“规则效能分析”的绝对神器。
*   因为日志表中记录了每一次打标对应的 `tag_id` 和 `rule_id`。
*   我们可以轻松地通过类似以下 SQL 在批处理结束后算出规则贡献度：
    ```sql
    SELECT rule_id, COUNT(*) as hit_count 
    FROM tag_task_logs 
    WHERE batch_id = ? AND action = 'add' 
    GROUP BY rule_id 
    ORDER BY hit_count DESC;
    ```

### 3.3 UI 与可视化选型
*   前端建议引入轻量级的图表库（推荐 `ECharts` 的 Vue3 封装版 `vue-echarts`）。
*   页面布局建议采用上下分层：
    *   **顶层（大盘概览区）**：展示核心大数字（覆盖率）与异常红牌预警（孤儿标签/失效规则）。
    *   **底层（深度钻取区）**：左侧展示标签分布的饼图/树图，右侧放置表格罗列每个规则的打标准确率与得分。

## 4. AI 智能研判的远期融合

在基础图表建立完善后，我们可以利用大模型进一步升级此模块：
*   **AI 诊断报告生成**：通过提取上述统计大盘数据（JSON 格式），投喂给 AI Copilot，要求其生成一份“人话”版的《打标资产健康度体检报告》。
*   *“系统检测到您的【羊毛党】标签下，规则B的命中率为0。结合您的其他数据，这可能是因为您的规则阈值（消费次数>100）设置得过于严苛，建议下调至 20 再次尝试。”*

## 5. 总结

引入**标签体系运营与分析模块**，标志着 TagMatrix 从“基础工具引擎”正式蜕变为**“闭环的策略优化平台”**。通过将庞杂的打标结果反向提炼为直观的监控指标，业务专家可以摆脱黑盒操作，进入“配置 -> 验证 -> 诊断评估 -> 调整迭代”的良性工程循环。
